# Заявки с сайта → @inrslead_bot → ваш личный чат

Код готов для серверной отправки через
[Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).
Активация требует токена бота, ID вашего личного чата и публикации изменений
в том Vercel-проекте, который обслуживает `www.inrsettle.com`.

## 1. Токен и рабочий домен

Сохраните токен @inrslead_bot в переменной `TELEGRAM_BOT_TOKEN` сервера.
Не публикуйте его в чате, GitHub, браузерном коде или URL, который открываете
в браузере. Название бота само по себе не даёт API-доступ.

Для локальной настройки можно скопировать `landing/.env.example` в
`.env.local` в корне проекта. Этот файл исключён из Git. Нужны:

```dotenv
SITE_URL=https://www.inrsettle.com
CONTACT_DELIVERY=telegram
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Адрес с `www` выбран потому, что `https://inrsettle.com` перенаправляет туда.
Если меняется основной адрес, обновите `SITE_URL` на фактический адрес формы.

## 2. Получить свой Chat ID

Откройте [@inrslead_bot](https://t.me/inrslead_bot) и нажмите Start.
Из корня проекта с Node 24+ выполните:

```sh
node --env-file=.env.local landing/scripts/telegram-chat.mjs
```

Скрипт проверит, что токен принадлежит именно @inrslead_bot, и покажет уникальную
команду `/start inrsettle-…`. Отправьте её боту **в своём личном чате**, затем
выполните вторую команду, которую покажет скрипт. Он выведет только ваш
`TELEGRAM_CHAT_ID`, соответствующий этой команде. Сохраните его в настройках.

Скрипт не отправляет сообщения, не выводит токен и чужую переписку,
не удаляет webhook и не подтверждает полученные обновления через `offset`.
Если у бота уже работает webhook, получите `message.chat.id` в его существующем
обработчике: скрипт остановится, сохранив настройки бота.

## 3. Включить на Vercel

В проекте сайта откройте Settings → Environment Variables. Добавьте четыре
переменные выше для Production. Токен пометьте как Sensitive.
Проверьте Settings → Build and Deployment:

| Настройка | Значение |
|---|---|
| Root Directory | Корень репозитория — поле пустое, без `landing` |
| Framework Preset | Other |
| Output Directory | `landing/public` |
| Build Command / Install Command | Пустые — заданы в корневом `vercel.json` |
| Node.js Version | 24.x |

В репозитории есть и `landing/vercel.json` для статического сайта. При Root
Directory `landing` серверный `api/contact.js` из корня не попадёт в deployment.
Vercel обнаруживает функции в папке `api` внутри корня проекта:
[документация конфигурации](https://vercel.com/docs/project-configuration/vercel-json#functions).

Сначала опубликуйте обновлённый код с `api/contact.js` и `landing/server/telegram.mjs`
в ветку, которую развёртывает этот Vercel-проект. Затем выполните новое
развёртывание. Изменения переменных окружения применяются к следующему deployment:
[документация переменных окружения](https://vercel.com/docs/environment-variables).

`GET https://www.inrsettle.com/api/contact` должен вернуть:

```json
{"available":true,"channel":"telegram"}
```

Это проверка наличия конфигурации, а не сетевой тест бота. Отправьте одну
контрольную заявку с формы и убедитесь, что в вашем личном чате пришли имя,
компания, email, тема, сообщение и выбранный маршрут.

## Поведение формы

- Секреты и получатель хранятся на сервере. Посетитель не может выбрать другой чат.
- Успех показывается после подтверждения Telegram для заданного личного чата.
- Длинная заявка приходит несколькими частями с одним номером обращения.
- При ошибке введённые данные остаются в форме, ложного сообщения об успехе нет.
- Если серверная отправка не настроена, форма предлагает подготовить письмо на info@inrsettle.com.

Telegram выбран основным каналом. Копия на email одновременно не отправляется.
Повторные запросы и уже подтверждённые части учитываются десять минут в одном
работающем экземпляре функции; это не гарантия отсутствия дублей между разными
экземплярами Vercel. Проверки реализации используют поддельные токены и
имитацию API, поэтому ни одного настоящего сообщения при тестах не отправлено.
